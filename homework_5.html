Riemann and Lebesgue sums, and the normal CDF by computation

Part 1 integrates the same functions twice, once by cutting the domain (Riemann) and once by cutting the range (Lebesgue), and compares accuracy, convergence and cost. Part 2 builds a fast and accurate routine for the standard normal CDF and explains why no closed formula exists. Part 3 is a list of automatic checks that this page runs on itself every time it loads.

Part 1 · Riemann and Lebesgue integration

Two ways to cut the same area

Riemann cuts the domain [a, b] into n cells of width h = (b − a)/n and takes one value of f in each cell. The cell is chosen first, the height is whatever f happens to be there.

Rn = h · Σk=0…n−1 f(a + (k + θ)·h),   θ = 0 left end, ½ midpoint, 1 right end

Lebesgue cuts the range with levels y0 < y1 < … < yM and asks, for each level, how much of the domain has f above it. The height is chosen first, the set is whatever preimage that height has. With μ the length (Lebesgue measure), stacking the layers gives two simple functions that trap f from below and from above:

lower:   sM = y0·(b − a) + Σk=1…M (yk − yk−1) · μ{ f ≥ yk }
upper:   SM = y0·(b − a) + Σk=1…M (yk − yk−1) · μ{ f > yk−1 }
sM ≤ ∫ f dμ ≤ SM,   SM − sM ≤ max(yk − yk−1) · (b − a)

The lower sum is the same thing as Σ yk·μ(Ek) with Ek = f−1([yk, yk+1)), written layer by layer. The bound on the gap holds for every bounded measurable f, however irregular, and that is the strength of the Lebesgue definition: it never asks f to be nearly constant on small intervals. As a single estimate I use the average (sM + SM)/2, called mid-level below.

How the preimages are measured

A Lebesgue sum is only as good as the measures μ{f > y} that go into it. Two versions are implemented.

Exact measure. Each function is described by the pieces on which it is constant or strictly monotone. On such a piece the set {f > y} is a single interval, and its end point is found by bisection (52 halvings, which is the full precision of a double). The lengths are added over the pieces. This is a true partition of the range: no grid on the x axis is involved.

Sampled measure. If f is a black box, the only way to measure a preimage is to sample f on a fine grid and count how many samples fall in each level. That count times h estimates μ(Ek). It is cheap, but it is really a Riemann sum whose values were rounded to the nearest level, so it cannot be better than the grid it uses.

Implementation

function riemann(F, n, off) {            // off = 0 left end, 0.5 midpoint, 1 right end
  const h = (F.b - F.a) / n;
  let s = 0;
  for (let k = 0; k < n; k++) s += F.f(F.a + h * (k + off));
  return h * s;
}

// length of {x in piece : g(x) > t}; g is monotone on the piece, so there is one crossing
function measureAbove(p, t, strict, cnt) {
  const above = v => strict ? v > t : v >= t;
  const A = above(p.ga), B = above(p.gb);            // values at the two ends
  if (A && B) return p.b - p.a;
  if (!A && !B) return 0;
  let inside = A ? p.a : p.b, outside = A ? p.b : p.a;
  for (let i = 0; i < 52; i++) {                     // bisection
    const m = 0.5 * (inside + outside);
    if (above(p.g(m))) inside = m; else outside = m;
  }
  return Math.abs(0.5 * (inside + outside) - (A ? p.a : p.b));
}

// lower += (y[k] - y[k-1]) * mu{f >= y[k]}     upper += (y[k] - y[k-1]) * mu{f > y[k-1]}

Levels are equally spaced between min f and max f. For the unbounded 1/√x they are geometric, from 1 up to T = M², and the part of f above T is left out (it is worth exactly 1/T here).

Pathological functions

Here the two definitions stop agreeing, and floating point stops helping: every double is a rational number, so sampling these functions on a computer shows only one of their two faces. The sums below are therefore computed exactly, with integers, from the structure of each function.

Dirichlet   f = 1 on the rationals, 0 on the irrationals. Every cell holds both kinds of point, so sup f = 1 and inf f = 0 on every cell: the upper Darboux sum is 1 and the lower is 0 for every n. The Riemann sum depends on the tags: tags k/n give 1, tags (k + 1/√2)/n give 0. There is no limit, so f is not Riemann integrable.
Lebesgue: the range has two values. ∫ f dμ = 1·μ(ℚ ∩ [0,1]) + 0·μ(irrationals) = 0, because a countable set has measure 0.
Thomae   f(p/q) = 1/q in lowest terms, 0 on the irrationals. It is discontinuous at every rational, but those form a null set, so by Lebesgue’s criterion it is Riemann integrable. With tags k/n, f(k/n) = gcd(k, n)/n. The upper Darboux sum uses sup f = 1/q on each cell, q being the smallest denominator of a fraction inside it.
Lebesgue: for t > 0 the set {f ≥ t} is finite (only denominators q ≤ 1/t), so every layer has measure 0 and the integral is 0 at once.
Fat Cantor set   f = 1 on the Smith–Volterra–Cantor set C, 0 elsewhere. C is built from [0, 1] by removing, at step j, an open middle gap of length 4−j from each of the 2j−1 intervals left. C contains no interval, so the lower Darboux sum is always 0, yet μ(C) = 1 − Σ 2j−1·4−j = ½, so the upper sums cannot go below ½. The discontinuities form a set of positive measure: f is not Riemann integrable.
Lebesgue: ∫ f dμ = 1·μ(C) = ½.

What the numbers say

On every Riemann-integrable function the two approaches converge to the same value, as the theory requires: a Riemann-integrable function on [a, b] is Lebesgue integrable with the same integral. In the table of all nine functions the two values differ by no more than the larger of the two errors, and the first check in Part 3 tests this agreement on every load. What differs is the speed.

For smooth functions (sin x, x², sin x / x, the bell) the midpoint rule gains two digits for every tenfold increase of n, error ∝ n−2. The Lebesgue mid-level sum is a trapezoid rule applied to y ↦ μ{f > y}, and that function has a square-root corner at every level where f is flat (a maximum or a minimum), so its error falls only like n−1.5. The lower and upper Lebesgue sums alone are first order: they differ by exactly Δy·(b − a).

The picture reverses when the difficulty lies in the domain. √x has a vertical tangent at 0: the midpoint rule drops to n−1.5, while cutting the range sees the smooth inverse function and keeps n−2. For 1/√x the Riemann sum with left tags is infinite and the midpoint sum converges like n−1/2, painfully slowly; the Lebesgue sum with geometric levels does not notice the singularity and reaches six digits at n = 10000. The Riemann integral exists here only as an improper limit, the Lebesgue integral exists directly.

Jumps are the other clear difference. For the two step functions a Riemann sum is exact only if the jump at ½ happens to be a grid node; otherwise one cell is wrong and the error is of order 1/n. The Lebesgue sum is exact for any number of levels (up to rounding of about 10−14), because each value has a preimage of known length. For |x − ½| the measure μ{f > y} = 1 − 2y is linear and the mid-level sum is exact too.

The price is the cost. A Riemann sum uses n evaluations. The exact-measure Lebesgue sum pays one bisection, about 52 evaluations, per level and per monotone piece, and it needs to know the monotone pieces in advance. The right-hand chart shows it: at equal work the midpoint rule wins on every smooth function, and Lebesgue wins only where Riemann struggles (1/√x, the steps). The sampled version costs the same as a Riemann sum and uses the same samples, so its accuracy is tied to the grid. It follows the Riemann error plus a rounding of up to half a level, which sometimes adds to it and sometimes cancels part of it; this is why its curve is irregular. On the smooth functions it is clearly worse than the midpoint rule, and on 1/√x it shows none of the gain of the exact-measure version. Partitioning the range pays off only when the preimages can be measured without a grid.

For the pathological functions the comparison is no longer about speed. Dirichlet and the fat Cantor indicator have Riemann sums that never settle, while their Lebesgue integrals, 0 and ½, follow from the measure of one set. Thomae shows that a dense set of discontinuities is harmless as long as it has measure zero. None of this can be seen by sampling in floating point; it comes from the measure of the sets.

Part 2 · The standard normal CDF

Φ(x) = ∫−∞x φ(t) dt,   φ(t) = e−t²/2 / √(2π)

Why there is no elementary formula

Elementary functions are those obtained from rational functions, exponentials, logarithms, roots and trigonometric functions by finitely many operations and compositions. Liouville’s theorem (1835) describes what the antiderivative of an elementary function must look like if it is elementary itself. For integrands of the form f·eg it becomes a simple test, in the version of Rosenlicht (1972):

If f and g are rational functions and g is not constant, then ∫ f(x)·eg(x) dx is elementary if and only if there is a rational function R with   R′ + g′·R = f.

The reason is that the only candidate for the antiderivative is R·eg, and differentiating it gives (R′ + g′R)·eg. For the normal density f = 1 and g = −x²/2, so the test asks for a rational R with

R′(x) − x·R(x) = 1

R has no poles. If R had a pole of order m ≥ 1 at some point, R′ would have a pole of order m + 1 there and x·R one of order at most m. They could not cancel, and the left side would be infinite at that point while the right side is 1.

R is not a polynomial either. If R is a polynomial of degree d ≥ 0, then x·R has degree d + 1 and R′ has smaller degree, so R′ − xR has degree d + 1 ≥ 1 and is not the constant 1. And R = 0 gives 0.

No such R exists, so ∫ e−x²/2 dx is not elementary, and neither is Φ. This is a statement about formulas, not about existence: Φ is a perfectly well defined, smooth, increasing function.

The error function: an exact name

erf(z) = (2/√π) ∫0z e−t² dt,   erfc(z) = 1 − erf(z)
Φ(x) = ½·(1 + erf(x/√2)) = ½·erfc(−x/√2)

The substitution t = u/√2 turns one integral into the other, so the representation is exact, not an approximation. Adding erf to the list of allowed functions gives Φ a closed form, and with it derivatives, series, asymptotic expansions and identities that can be handled symbolically.

It does not give digits. erf is only a name for the same integral, and somebody still has to evaluate it: a library erf is itself a numerical method (typically rational approximations on several intervals). The same is true of ex or sin x, which a processor also computes by approximation. So the numerical question remains, and it has a real difficulty of its own: the left tail of Φ is tiny, and a method that is fine in the centre can lose every significant digit there.

Methods compared

Trapezoid and Simpson. Φ(x) = ½ ± ∫0|x| φ, with n equal panels. Errors of order h² and h⁴.
Maclaurin series. Φ(x) = ½ + (1/√(2π)) · Σk≥0 (−1)k x2k+1 / (2k · k! · (2k+1)), the power series of erf integrated term by term. The signs alternate.
erf approximation. Φ(x) = ½(1 + erf(x/√2)) with the classical formula 7.1.26 of Abramowitz and Stegun, erf(z) ≈ 1 − (a1t + … + a5t⁵)·e−z², t = 1/(1 + pz), absolute error below 1.5·10−7.
Final method. Work with the upper tail Q(x) = 1 − Φ(x) for x ≥ 0 and use Φ(−x) = Q(x).
 • centre, x < 1.5:   ∫0x φ = φ(x)·(x + x³/3 + x⁵/(3·5) + x⁷/(3·5·7) + …). All terms are positive, so nothing cancels.
 • tails, x ≥ 1.5:   Q(x) = φ(x) / (x + 1/(x + 2/(x + 3/(x + …)))), Laplace’s continued fraction, evaluated from the inside out with ⌈8 + 420/x²⌉ levels.

The point of the final method is that a small probability is never obtained as 1 minus a number close to 1. Both formulas carry the factor φ(x), so the tail keeps its relative accuracy all the way down. The number of levels was fitted by experiment: it is the smallest count that makes the fraction stationary to 16 digits, with a margin.

const SPLIT = 1.5;
function centreSeries(a) {              // integral of phi from 0 to a
  let term = a, sum = a;
  for (let n = 1; n < 200; n++) {
    term *= a * a / (2 * n + 1);
    sum += term;
    if (term < 1e-17 * sum) break;
  }
  return phi(a) * sum;
}
function tailFraction(a) {              // Q(a) for a >= SPLIT
  let t = a;
  for (let k = Math.ceil(8 + 420 / (a * a)); k >= 1; k--) t = a + k / t;
  return phi(a) / t;
}
function upperTail(x) {                 // Q(x) = 1 - Phi(x)
  if (x !== x) return NaN;
  if (x < 0) return 1 - upperTail(-x);
  if (x > 38.5) return 0;               // below the smallest double
  return x < SPLIT ? 0.5 - centreSeries(x) : tailFraction(x);
}
function normalCdf(x) {
  if (x !== x) return NaN;
  return x <= 0 ? upperTail(-x) : 1 - upperTail(x);
}

What the numbers say

The final method agrees with the Wikipedia values to all 15 published decimals and with the NIST table to all 5, and its relative error against the 50-digit reference stays within a few units of 10−15 from x = −10, where Φ ≈ 7.6·10−24, to x = 10. It needs at most about 20 terms of the series or about 200 levels of the fraction (at the switch point, fewer and fewer further out), and no tuning by the user.

Trapezoid and Simpson behave exactly as their theory says, with slopes −2 and −4 in the convergence plot, and Simpson with 200 panels is accurate to about 10−11 in absolute terms. But they cost 200 evaluations of φ per call, which makes them more than ten times slower than the final method, and they return ½ − ∫ for negative x: a rounding error of 10−16 in that subtraction is harmless near the centre and fatal when Φ(x) itself is 10−10 or smaller.

The Maclaurin series is excellent near 0 and breaks down for large |x|. Its terms grow to about ex²/2 before they start to decrease, with alternating signs, so the sum loses that many digits to cancellation. The formula of Abramowitz and Stegun is the cheapest of all and keeps its promise of 7 correct decimals, which is useless in relative terms once Φ(x) is below 10−7.

This matters in practice. In intrusion and anomaly detection an alert threshold at k standard deviations has a false-positive rate of Q(k), and a p-value is a tail probability: these are exactly the small numbers that the naive methods get wrong. One caution applies to every method: far in the tail the problem itself is sensitive, since a relative change δ in x changes Φ(x) by about x²·δ. For this reason the reference points were chosen to be exactly representable in binary (multiples of 1/8).
