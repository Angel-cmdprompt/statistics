Experiment 01

Public-key encryption with secp256k1

Here, the receiver uses a secp256k1 key pair, but the secret scalar is intentionally chosen from just 5,000 possibilities so an attack can be demonstrated in a browser. The construction below is a simplified ECIES-style exercise: SHA-256 expands a shared point into a keystream, which is XORed with the message. It is for learning only and does not authenticate the sender or ciphertext.

Who holds which key?

The receiver keeps d private and shares Q = dG. For each encryption, the sender chooses a fresh random r and sends R = rG. Both sides can derive the same shared point: sender computes rQ, while receiver computes dR.

What happens, in order

First, the receiver publishes a point derived from the secret scalar. The sender creates a temporary key and a shared point, then hashes that point with a counter to generate enough bytes for the message. XOR combines those bytes with the plaintext. The receiver recreates the shared point using the private scalar and reverses the XOR operation.

Scope of this model

A deployed system should use a standard, reviewed protocol with a suitable key-derivation function, authenticated encryption, validated curve points, and robust implementation practices. The simplified construction here is not a substitute for those safeguards.

Experiment 02

A shift cipher in action

Each alphabetic character moves by the chosen number of places around the 26-letter alphabet. To undo the operation, shift in the opposite direction. This page leaves spaces, punctuation, and uppercase/lowercase styling untouched.

Why it is easy to break

The key has just 26 values. An attacker can list every possible decoding in seconds, so the cipher offers almost no practical secrecy.

Experiment 03

Guessing the shift from language patterns

English prose does not use every letter equally often. The program tests all shifts, counts letters in each candidate plaintext, and compares those counts with a reference English distribution using a chi-squared score. The lowest score is its best guess, though short or unusual text can fool it.

When it works well

As a sample grows, letter counts tend to become more representative of English. Since a Caesar shift merely renames letters, the overall frequency pattern survives and can reveal the shift.

Where it can fail

A few words may not contain enough letters to reveal a stable pattern. Proper names, technical terms, quotations, and text in another language can also make standard English frequencies a poor reference.

Other ways to attack it

Brute force prints all 26 possible decodings and leaves selection to a person or a ranking method. Single-letter analysis compares letter counts. N-gram scoring checks common pairs and triples of letters, which can provide extra clues but requires language data.

Reference language data

A large known-language collection can be used to estimate letter and n-gram probabilities. This version uses commonly cited English letter percentages as a fixed baseline; it does not train on a custom corpus.

Recovering the toy ECC key

The attack repeatedly adds the generator point to produce G, 2G, 3G, … and checks each result against the public point Q. A match reveals d. With that scalar, the attacker derives dR and reproduces the keystream. The weakness is the tiny allowed range, not the curve’s intended security.

Why normal ECC is different

A correctly generated secp256k1 key has an astronomically large set of possible secret scalars, making a simple search infeasible. Security can still be undermined by poor randomness, side-channel leaks, faulty implementations, invalid-point bugs, or protocol mistakes; those are different problems from the homework’s restricted range.
